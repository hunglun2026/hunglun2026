ChromeOS Flex 大量部署：Intune 篇

已經被 Intune 管理的一大批 Windows 電腦（以 4000 台 Surface Go 為例），從盤點、打包、試點到分批推送，轉成 ChromeOS Flex 並在轉換時自動註冊、綁定 CEU。

0先看結論

CEU 不能「先刷完再綁」
CEU 是在電腦第一次開機註冊的那一刻自動綁上去的，註冊靠的是轉換時就寫進去的註冊權杖。所以權杖一定要在轉換的同一次放進去。轉換時沒放權杖，4000 台之後就只能派人到現場一台一台按 Ctrl+Alt+E 手動註冊。
問題答案
一定要用 FRD 嗎？不一定，但要遠端、不派人到現場，FRD 是 Google 唯一的官方做法。其他方法（隨身碟、網路開機）每台都要有人在旁邊操作，第 2 章有比較
Surface Go 能做嗎？Go 2、Go 3 可以（Google 通過認證，支援到 2028 年）。Go 第一代、Go 4 不行（不在認證清單上）
順序是什麼？買好 CEU → 產生權杖 → Intune 盤點 → 打包（權杖放進去）→ 試點 → 分批推送 → 每台第一次開機自動註冊、扣 CEU
Intune 後台看得到結果嗎？看得到。我們的 intune-install.ps1 用結束代碼回報每台是「模擬通過」「已開始轉換」還是哪一種失敗（第 12 章）
這份手冊的驗證狀態（2026-10-02）
  • 已驗證 官方資料：認證清單、FRD 檢查項目、Intune 與 Surface 的設定方式，都已經抓官方原文逐字核對
  • 已驗證 三方查核：8 個官方原文沒寫清楚的細節，先問 Gemini、再請 ChatGPT 審稿，最後由我們對照官方原文定案。兩個 AI 講得太有把握、但查無官方依據的說法（例如「Surface 出廠一定擋 Flex」「4GB 機型一定失敗」）都沒有寫進來，改列在第 18 章的「無法確認」
  • 已驗證 intune-install.ps1：用模擬的 agent.exe 跑過六種情況（含 32 位元啟動），結束代碼都正確；打包程式實際產出 1GB 的 .intunewin，安裝檔名正確
  • 未實測 真的 Intune 環境、真的 Surface Go、真的 agent.exe 轉換。所以第 13 章的試點一定要做，不能跳過

2一定要用 FRD 嗎

Google 官方有四種裝 Flex 的方式。差別在於「每台電腦要不要有人在旁邊操作」。

方式每台要做的事能自動綁 CEU 嗎4000 台 Surface Go
FRD（遠端轉換）不用碰。Intune 推過去，自己轉、自己重開機能，權杖寫在設定檔裡推薦，唯一能遠端的官方做法
一般 USB 隨身碟插隨身碟、開機時按住音量鍵選隨身碟、按安裝、等 10～20 分鐘、手動註冊不能，要在登入畫面按 Ctrl+Alt+E 手動註冊4000 台要上百人次到現場，不建議
封了權杖的 USB插隨身碟開機安裝，第一次開機自動註冊能還是要每台插隨身碟。適合當 FRD 失敗機的備案
網路開機（SCCM／WDS）每台設定從網路開機（PXE），要接網路線能Surface Go 沒有網路線插孔，要另外買 USB 網路卡，而且客戶要有 SCCM 或 WDS 伺服器，不建議
FRD 要不要申請？
Google 總覽頁寫「填表取得 FRD」，但快速入門頁直接給了下載網址 dl.google.com/cros-frd/frd-latest.zip，我們工具就是從這裡下載的，不用等回信。不過 4000 台是大案子，建議你用 Google Partner 的身分同時填表並聯絡 Google，出問題時才有官方窗口。
結論
客戶已經有 Intune，電腦也都在 Intune 裡，FRD＋Intune 是最省人力的路。隨身碟當備案，給 FRD 失敗、又確定要轉的少數電腦用。

4GB 記憶體的機型要特別測
Go 2、Go 3 都有 4GB 和 8GB 的版本。Google FRD 的檢查寫「至少 4GB 記憶體」，但官方沒寫是拿哪個數字比，4GB 機型會不會剛好卡在門檻，無法確認。試點時一定要放一台 4GB 的（第 13 章）。

4開工前跟客戶確認

  • CEU 數量：管理控制台 → 帳單 → 訂閱，CEU 數量要大於等於這次要轉的台數
  • 機型分布：Go 2、Go 3 各幾台，4GB 與 8GB 各幾台，放在哪幾個校區或網路（試點要每一種都涵蓋）
  • 兩個管理員帳號：Google 管理控制台（有 Chrome 管理權限）、Intune 系統管理中心（能建應用程式與群組）
  • 資料備份：轉換會清空整台電腦。學生的檔案要先同步到 OneDrive 或雲端硬碟，書面確認
  • 2028 支援期限：書面確認（第 3 章）
  • 註冊用 Wi-Fi：能不能開一個用密碼連的臨時 Wi-Fi（第 9 章）
  • 時段：哪幾天電腦可以集中放在充電車上、開機、連網，不給學生用
  • 現場窗口：失敗機需要有人去現場處理（按鍵、插隨身碟），誰負責、什麼時候能去
  • Windows 之後還要不要：決定第 17 章要不要把電腦從 Autopilot 移除

PART 2

準備

在 Intune 和 Google 兩邊把條件備齊。到這裡為止，電腦都還沒被動到。

5從 Intune 盤點

  1. Intune 系統管理中心 → 裝置 → Windows（或「所有裝置」）
  2. 按「資料行」加上這些欄位：裝置名稱、序號、型號、作業系統版本、上次簽入時間、總儲存空間、可用儲存空間、實體記憶體（Microsoft 官方：所有裝置清單可以自選欄位並匯出，報表欄位名稱是 StorageFree、StorageTotal）
  3. 按「匯出」，下載成 Excel 檔
  4. 照下表篩選，每台標上「合格」或不合格的原因
欄位合格條件不合格怎麼辦
型號Surface Go 2 或 Surface Go 3第一代、Go 4 不轉，跟客戶說明
可用儲存空間10GB 以上（10240MB）第 7 章清空間
總儲存空間32GB 以上（Surface Go 都符合）不轉
上次簽入時間最近 7 天內不在線上的推不到。請客戶找出電腦、開機連網
作業系統Windows 10 或 11 的專業版、教育版、企業版S 模式看第 6 章
序號很重要，留著
Google 管理控制台的裝置清單也有序號。之後用序號對照 Intune 名單和 Google 名單，就知道哪幾台轉完、哪幾台卡住（第 15 章）。

建群組

在 Microsoft Entra 系統管理中心建「指派的」（靜態）裝置群組，命名建議：

Flex-00-試點        5～10 台
Flex-01-第一批      30 台（一個班）
Flex-02-第二批      200 台
Flex-03-第三批      500 台
...
大量加成員要注意 ID
Entra 群組的「匯入成員」CSV 欄位是「成員物件識別碼或 UPN」，裝置要填 Entra 的物件識別碼。它跟 Entra 的「裝置識別碼」、Intune 的「裝置識別碼」三個都不是同一個值，不要拿 Intune 匯出的 ID 直接匯入。幾百台以上請客戶的 IT 用 Microsoft Graph PowerShell 依序號或裝置名稱加入群組，不要手動一台一台點。

匯出後長什麼樣

匯出之後在 Excel 篩選

  1. 先看一兩列，確認「可用儲存空間」的單位：Intune 畫面是 GB，匯出檔可能是位元組，數字差一個很大的倍數，單位弄錯整批都會誤判
  2. 型號欄：用「篩選」只留 Surface Go 2、Surface Go 3，其餘貼到「不轉」分頁，備註原因
  3. 空間欄：小於 12GB 的列入「先清空間」（12GB 是 10GB 加上安裝包的緩衝，見第 7 章）
  4. 簽入時間欄：超過 7 天的列入「找人開機」
  5. 留下序號欄：之後第 15 章對帳全靠序號

幾百台以上：用 Graph 批次加進群組

手動點是做不完的。請客戶的 IT 或你自己用 Microsoft Graph PowerShell，依裝置名稱找到 Entra 的物件，再加進群組。下面是做法的樣子，未實測，用之前先在 3 台上試：

# 需要先裝 Microsoft.Graph 模組，並用有權限的帳號登入
Connect-MgGraph -Scopes "Group.ReadWrite.All","Device.Read.All"

$group = Get-MgGroup -Filter "displayName eq 'Flex-01-第一批'"
$names = Get-Content .\第一批裝置名稱.txt          # 一行一個裝置名稱

foreach ($n in $names) {
    $dev = Get-MgDevice -Filter "displayName eq '$n'"
    if ($dev) { New-MgGroupMember -GroupId $group.Id -DirectoryObjectId $dev.Id }
    else      { "找不到：$n" }
}
這裡用的是 Entra 的物件 ID
$dev.Id 就是前面警告過的「物件識別碼」，所以不會踩到 ID 搞混的問題。同名的裝置可能不只一筆（重灌過的電腦），遇到就改用序號對照。

6退出 S 模式

教育版 Surface Go 有些出廠是 S 模式。這是必要條件：Microsoft 官方寫「Intune 管理延伸模組不支援 S 模式，因為 S 模式不允許執行非市集的 App」，而 Win32 應用程式就是靠這個模組安裝的。S 模式的電腦一定要先退出。

Microsoft 兩份文件的說法不一樣
Win32 應用程式的總覽頁寫「支援 S 模式裝置」，管理延伸模組的頁面寫「不支援 S 模式」。我們照比較嚴格的那份做，先退出 S 模式就兩邊都不會出問題。
  1. Intune 系統管理中心 → 裝置 → 管理裝置 → 組態 → 建立 → 新原則
  2. 平台選「Windows 10 及更新版本」，設定檔類型選「範本 → 版本升級和模式切換」
  3. 設定：模式切換選「切換出 S 模式」
  4. 指派給要轉的群組，裝置下次簽入時就會套用
單向的
Microsoft 官方：退出 S 模式後就回不去了。反正這批電腦之後要轉成 Flex，沒有影響。
電腦下次簽入還沒套用：請現場把電腦開機連網，或在電腦上手動「同步」。套用後，電腦的「設定 → 系統 → 關於」會顯示不再是 S 模式。這個查看位置依 Windows 版本可能不同，不確定時就用 Intune 裝置頁的狀態為準

7空間不夠怎麼辦

Surface Go 2、Go 3 都有 64GB 的版本，裝了 Windows 和更新後常常只剩幾 GB。我們的腳本要求可用 10GB：Google 官方已知問題寫「部分裝置需要 9GB」，再加上複製安裝包約 1GB。

  • 先在 Intune 應用程式設定「需求：所需磁碟空間 10240MB」（第 11 章）。空間不夠的電腦會顯示「不適用」，不會跑到一半失敗
  • 清理方式：學生檔案確定備份後刪除下載資料夾與桌面的大檔案、清空資源回收筒；用 Intune 開啟「儲存空間感知」自動清暫存檔；移除用不到的大型 App
  • 清不出來的：列入「現場處理」名單，改用封了權杖的 USB 安裝（第 16 章）
安裝包本身也佔空間
Intune 會先把約 1GB 的安裝包下載到電腦的暫存資料夾，再執行我們的腳本。所以實際需要的空間比 10GB 再多一點，盤點時抓 12GB 比較保險。

8Google 管理控制台

這一章由客戶的 Google 管理員操作，你在旁邊確認。

  1. 確認 CEU 數量：帳單 → 訂閱，Chrome Education Upgrade 的可用數量要夠
  2. 建組織單位：目錄 → 組織單位，例如 學生裝置/Flex-SurfaceGo。所有轉好的電腦都會註冊到這裡
  3. 先在這個組織單位設好政策：
    • 裝置 → Chrome → 設定 → 裝置：誰可以登入（例如只允許學校網域帳號）、自動更新設定
    • 裝置 → 網路 → Wi-Fi：加入學校正式的 Wi-Fi（包含要帳號密碼的 802.1X 網路）。註冊完成後會自動派送到電腦
  4. 產生註冊權杖：裝置 → Chrome → 註冊權杖 → 註冊，選剛才的組織單位，複製權杖
權杖是機密
拿到權杖的人都能把電腦註冊到客戶的網域、用掉 CEU。只放在工具的設定裡，不要貼在聊天群組或公開文件。
為什麼要「先設政策、再產生權杖」
電腦註冊完成的那一刻，會立刻套用這個組織單位的政策（包含學校正式的 Wi-Fi）。如果政策還沒設，電腦註冊成功但連不上學校網路，現場就會一片「註冊了卻不能用」。

9註冊用的 Wi-Fi

Surface Go 沒有網路線插孔。轉完第一次開機，只能靠我們預先寫進去的 Wi-Fi 連上網，連上才能註冊。所以這個 Wi-Fi 要「保證連得上」。

項目建議為什麼
加密方式WPA2 個人版（用密碼連）Google 官方：FRD 會忽略 ONC 裡的 CA 憑證，建議「ONC 只用來讓電腦第一次連上網，其他設定等註冊後再派送」。學校正式的 802.1X 網路就是要等註冊後由管理控制台派送
名稱臨時專用，例如 Flex-Enroll專案結束就關掉，密碼外流也沒關係
DHCP位址池要大於一批的台數（例如 500 台一批就要 500 個以上）同時開機的電腦拿不到 IP 就註冊不了
防火牆放行 Google 的註冊與更新網址註冊要連到 Google。請客戶網管照 Google 官方的 ChromeOS 網路需求設定
覆蓋範圍充電車擺放的地方訊號要好一次幾百台同時連，基地台容量也要夠
Wi-Fi 密碼含雙引號或反斜線
2026-10-05 前的工具會把密碼原樣貼進 wifi.onc，密碼裡有 " 或 \ 時檔案會壞掉，而 FRD 不檢查，結果是整批電腦註冊失敗。現在的工具會自動跳脫並驗證產出的 JSON；如果手上是舊版工具包，請先更新。

一定要先測網路設定檔

Google 官方特別強調：FRD 不會檢查 ONC 網路設定檔寫得對不對，寫錯的話所有電腦都會註冊失敗。4000 台的案子，這一步不能省：

  1. 產生安裝包後，從工具的 FRD 資料夾（tools\frd-package）複製 wifi.onc
  2. 找一台 ChromeOS 裝置（任何 Chromebook 或已經裝好 Flex 的電腦），網址列打 chrome://network
  3. 最下面「Import ONC File」，選這個檔案
  4. 打開 chrome://device-log/，上方按 Clear Types 再只勾 Network，確認沒有匯入錯誤，而且這台真的連上了註冊用 Wi-Fi
開不出臨時 Wi-Fi、只能用 802.1X：ONC 格式本身支援 802.1X，但我們工具還沒做這種設定，也沒測過。這種情況請先跟我們討論
手上沒有 ChromeOS 裝置怎麼辦
試點的那一台就是最好的測試：不要先批次推送，先看那一台轉完能不能連網註冊。但那樣一旦 ONC 有錯，你會浪費一次轉換（要現場重灌），所以能借到任何一台 Chromebook 先測，是最划算的。

  • Intune：已經轉成 Flex 的電腦，在 Intune 裡會一直停在最後一次簽入的狀態。選取後「淘汰」或「刪除」，避免留下幾千筆用不到的紀錄

20名詞解釋

FRD
Google 官方的 ChromeOS Flex 遠端轉換工具，核心是 agent.exe。在 Windows 裡執行就能把整台轉成 Flex
CEU
Chrome Education Upgrade，買在客戶 Google 網域裡的授權。電腦註冊時扣一個，之後才能集中管理
註冊權杖
客戶管理控制台產生的一串碼，綁在組織單位上。寫進安裝包，轉好的電腦第一次開機就用它註冊
Win32 應用程式
Intune 派送一般 Windows 程式的方式，要先用 Microsoft 的工具打包成 .intunewin
結束代碼（傳回碼）
程式結束時回報的數字。Intune 依這個數字顯示成功、失敗、重新開機或重試
偵測規則
Intune 用來判斷「這台裝好了沒」的條件。我們用標記檔：模擬通過留 dryrun-ok.txt，開始轉換留 install-started.txt
傳遞最佳化
Windows 的下載分享功能，同一個網路的電腦會互相傳已經下載的內容，減少對外頻寬
dry_run（模擬）
FRD 只做檢查、不動硬碟的模式
ONC
Google 的網路設定格式，用來預先寫入 Wi-Fi。需要有權杖才生效
S 模式
Windows 的限制模式，只能裝 Microsoft Store 的 App
Secure Boot
開機時檢查系統有沒有可信任的簽章，沒有就不讓它開機
DFCI
Intune 遠端管理電腦韌體設定的功能，Surface 只有部分型號支援
組織單位（OU）
Google 管理控制台裡的資料夾，政策與註冊權杖都綁在它上面。轉好的電腦會註冊到指定的組織單位
群組（Entra 裝置群組）
Intune 派送的對象。我們用「指派的」靜態群組，一批一個，方便分批
.intunewin
用 Microsoft 工具把安裝包壓成的格式，上傳到 Intune 才能派送
標記檔
腳本做完該做的事才寫出的小檔案（dryrun-ok.txt、install-started.txt），給偵測規則判斷用
Microsoft Graph PowerShell
用指令操作 Microsoft 雲端服務的工具，大量加群組成員時用
TPM
主機板上的安全晶片。部分機型轉換前要清除，FRD 會自動嘗試

22常見問題

轉換到一半沒電會怎樣？
開始前腳本會檢查有沒有插電，沒插就回 1618 不動硬碟。轉換進行中斷電會怎樣，官方沒寫，無法確認，所以一定要用充電車、全程插電。
學生與老師的檔案會留下來嗎？
不會。轉換會清空整台電腦。這就是第 4 章要客戶書面確認備份的原因。
轉完還能回 Windows 嗎？
要到現場，用 Windows 安裝媒體一台一台重灌，也要有可用的 Windows 授權。我們沒有查到可以遠端回復的官方做法。
模擬版通過，正式版就一定成功嗎？
不一定。模擬只能抓到「轉換前」的問題。轉換之後的狀況（例如 Secure Boot 設定讓 Flex 開不了機、安裝失敗、Wi-Fi 設定檔有錯）模擬看不到，這就是要先做試點的原因。
既然正式版自己會先模擬一次，為什麼還要模擬版？
模擬版的價值是「先知道哪些電腦不合格」，不合格的在 Windows 裡就被擋下來、不會進到轉換。如果直接推正式版，不合格的電腦一樣不會被動到，但你會晚一點才知道哪些要處理。
Intune 一直顯示「安裝中」，是卡住了嗎？
正式版常常是這樣。agent.exe 約 2 分鐘內自己重開機，腳本來不及回報。以 Google 管理控制台有沒有出現這台為準（第 12、15 章）。
要先把 BitLocker 關掉嗎？
官方只確定一件事：BitLocker 開著時，不要從韌體清除 TPM。我們從 agent.exe 的程式內容看到它會自己下 Disable-BitLocker 與 Clear-Tpm，推測不用手動先關，但這不是官方說明、也沒有真機驗證。試點機保持客戶原本的設定跑一次，結果就是答案。
一次同時 500 台連臨時 Wi-Fi，撐得住嗎？
要看基地台與 DHCP。所以第二批才放 200 台，先看有沒有網路相關的失敗，再放大。
沒有買 CEU，也能轉嗎？
技術上可以（權杖空白就不註冊），但轉完是「未受管」的 Flex，之後沒有遠端集中註冊的辦法。4000 台的案子不建議。
臨時 Wi-Fi 的密碼被學生知道了怎麼辦？
它只用在轉換後第一次連網，註冊完就會換成管理控制台派送的正式 Wi-Fi。專案期間用 WPA2 密碼加上固定時段開啟，結案就關掉。
轉換要花多久？
Google 官方沒有寫。試點時用計時器量，量到的數字就是之後排批次的依據（第 13 章）。
