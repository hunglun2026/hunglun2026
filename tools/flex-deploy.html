這個工具在做什麼

先弄懂原理，後面每個步驟才知道自己在幹嘛。

Google 官方有一套叫 FRD（ChromeOS Flex Remote Deployment）的工具，是一支 Windows 執行檔 agent.exe 加上一個設定檔。把它推送到還在跑 Windows 的電腦上執行，它會自動完成四件事：

  1. 清除 TPM、重新分割整顆硬碟
  2. 安裝 ChromeOS Flex
  3. 連上你指定的 Wi-Fi
  4. 用註冊權杖自動加入 Google Admin Console

我們這套系統做的事，是把「怎麼把這支程式送到幾十台電腦上跑」自動化，並包成一個不用打指令的操作畫面。

這是不可逆的操作

執行之後，那台電腦原本的 Windows 與裡面所有資料會被清空，變成 ChromeOS Flex，救不回來。所以整套流程都圍繞著一件事設計：先用模擬測試確認，再動真的。

適用機型：只做官方認證的型號

未認證的機器不要碰

Google 官方明文寫著：「裝置如果未列在認證裝置清單中，就不適用 Chrome Education 或 Chrome Enterprise 支援服務。」對學校客戶來說這是大事，他們付錢買了 Chrome Education Upgrade，裝在未認證機器上等於自己放棄支援資格。

接案前第一件事就是拿對方的機型去對 Google 的通過認證的型號清單。清單上的每個型號有四種狀態，只有第一種可以做：

狀態官方定義我們的做法
通過認證 裝置型號預期可與 ChromeOS Flex 搭配運作 可以接。這是唯一建議部署的狀態
預期會出現輕微問題 可能至少可以支援基本功能，但團隊仍在改善相容性 先跟客戶說清楚有風險，並實測過再決定
預期會出現重大問題 已知會出現啟動問題等重大問題，目前不建議搭配使用 不要做
取消認證 已達支援終止日期，支援服務於指定年度 12 月 31 日結束 不要做

未列在清單上的機型，Google 的說法是「如果您可以接受可能發生問題的情況，可以嘗試安裝」，但同時警告「即便未經認證的裝置功能完全正常，還是可能隨時出現重大問題」，而且「無法保證 OS 定期更新的穩定性、功能或效能」。

換句話說，技術上裝得起來，但那是個人自己玩的層級，不是商用交付該做的事。我們對外承接一律只做通過認證的型號。

清單更新得很頻繁（官方頁面會標最後更新日期），每次接案都要重新查一次，不要靠記憶或舊資料。

開始之前要準備

缺任何一項都做不下去，出發前先對一次。

要準備的哪裡拿備註
確認機型通過認證 Google 官方認證型號清單 接案第一件事。狀態不是「通過認證」的機型不要做，客戶會失去 Chrome Education 支援資格
確認是不是 S 模式 裝置上：設定 → 系統 → 啟用 Surface Go 出廠預設就是 S 模式。是 S 模式的話整條路要換走法，見「該走哪條路線」
ChromeOS Flex 註冊權杖 對方單位的 Google Admin Console 路徑：裝置 → Chrome → 註冊權杖 → 註冊 → 選「非 ChromeOS 裝置（採用 ChromeOS Flex）」→ 自動註冊。需要 Chrome 管理員權限，權杖沒有到期日
Wi-Fi 名稱與密碼 現場網管 裝置轉完 ChromeOS Flex 之後要靠這組連網才註冊得上
官方套件（約 1 GB） 介面上按「準備套件」自動下載 出發前先在公司網路下載好，現場才不用等
一到兩台測試機 現場挑 絕對不能跳過。整批下去之前一定要有機器先跑過

權杖不用等裝置存在，先產生就對了

很容易誤會成「裝置要先裝上 CEU 才會有權杖」，順序其實是反過來：權杖是綁在「組織單位」上的通用碼，不是綁在某一台裝置上。管理員可以在任何裝置都還沒出現的情況下，直接在 Admin Console 對著要用的組織單位按「產生」，馬上拿到一組。

真正的前提是那個帳號的授權池裡要有剩餘的 CEU 名額（也就是學校真的買夠了），這是採購問題不是裝置問題。裝置實際拿權杖去註冊的那一刻，才會從授權池扣掉一個名額綁給它。

帶哪台電腦去很重要

那 1 GB 的官方套件放在工具資料夾底下的 tools\，這個資料夾刻意不進版本控制、也不進備份（不然會把公司的程式碼倉庫撐爆）。意思是它不會自動同步到別台電腦。請帶已經按過「準備套件」的那台去現場；帶別台的話，現場得用當地網路重抓 1 GB。

三分鐘上手

第一次用照這裡做就好，細節在後面章節。

  1. 雙擊「開始操作.bat」

    瀏覽器會自動打開操作畫面。這支服務只跑在你自己的電腦上，別人連不進來，關掉黑色視窗就結束。

  2. 輸入系統密碼

    跟公司 CEU 綁定系統同一組密碼。

  3. 按右上角「準備套件」

    第一次要下載約 1 GB 的官方檔案，記錄區會顯示進度。下載過一次之後就不用再按。

  4. 填三個欄位並儲存

    註冊權杖、Wi-Fi 名稱、Wi-Fi 密碼。三個沒填完，下面的執行按鈕會是灰的按不下去。

  5. 確認是綠色的模擬測試模式

    畫面中間那條大橫幅是綠色就對了。這個模式只做檢查，不會動任何硬碟。

  6. 選路線並執行

    要走 Intune 就按「開始產生安裝包」；要直接遠端部署就切到 PsExec 分頁，填裝置清單後按「開始部署」。

路線 A：必須用 Intune

符合任一條件就算，不是選喜好，是裝置的狀況逼你只能走這條。

符合任一項，就是這條路線

① 裝置是 S 模式（Surface Go 系列出廠預設就是）　② 被 Intune／Entra ID 管理（員工用公司 Microsoft 帳號登入，不是傳統網域帳號）　③ 裝置分散各地，你人到不了、也連不進內網　④ 對方資安政策擋掉 445 埠檔案分享

  1. 確認機型通過 Google 認證

    對照Google 官方認證型號清單，精確比對機型名稱與型號。狀態不是「Certified」不要接，客戶會失去 Chrome Education 支援資格。Surface Go 系列注意：查證過只有 Surface Go 2、Surface Go 3 是 Certified（支援到 2028 年），第一代 Surface Go 不在清單上，務必請客戶開「設定 → 系統 → 關於」核對完整機型名稱。

  2. 檢查是不是 S 模式

    在裝置上開「設定 → 系統 → 啟用」，版本名稱寫著「S 模式」就是（Surface Go 出廠預設就是）。S 模式的 Windows 不允許安裝執行 Win32 應用程式，而這個工具的核心程式 agent.exe 正是 Win32 程式，檔案送得過去也跑不動，換 PsExec 也沒用，因為問題不在傳輸方式。

  3. 是 S 模式的話，用 Intune 政策整批退出

    有 Intune 授權可以整批遠端退出，不用一台一台跑；沒有的話每台自己到 Microsoft Store 手動退出。這一步是單向的，退出後回不去 S 模式，但反正接下來整台都要變成 ChromeOS Flex，這點不構成問題。

  4. 確認是 Entra ID 環境（PsExec 用不了的原因）

    Entra ID 環境的裝置在網路驗證上被當成「工作群組」電腦，沒有傳統網域管理員帳號可用，而 PsExec 正是靠那組帳號連進去的。所以只要是 Entra ID 管理，不管是不是 S 模式，都只能走 Intune。

  5. 備妥權杖、Wi-Fi、官方套件

    到對方的 Google Admin Console 產生 ChromeOS Flex 註冊權杖，跟現場網管要 Wi-Fi 名稱密碼，出發前先在公司網路用介面「準備套件」按鈕把約 1GB 的官方套件下載好。完整清單見「開始之前要準備」。

  6. 照 Intune 路線細節執行

    照「Intune 路線細節」把 agent.exe 打包成 Win32 App、指派給目標裝置群組，裝置自己向雲端報到拉下來安裝，不用人在現場。

  7. 先跑 1～2 台模擬測試

    介面上的 dry_run 模式只檢查不動硬碟，綠色橫幅代表過了。整批下去之前這一步絕對不能跳過，詳見「模擬測試與正式部署」。

  8. 正式部署與現場流程

    模擬測試通過後才關掉 dry_run 跑正式的。完整現場動線（到場前、到場後、交件前）見「現場完整流程」。

  9. 驗收

    照「怎麼確認成功」的檢查清單逐台過一遍，都通過才算完工交件。

路線 B：可以用 PsExec

要同時符合下面四個條件才走這條，速度最快，填一填就跑完。

四個條件要全部符合

① 裝置不是 S 模式　② 是傳統網域環境，不是 Entra ID Only　③ 你人在現場、跟裝置同一個網段連得到　④ 手上有網域管理員帳密

缺一項就要改走「路線 A：必須用 Intune」，不是機型決定，是裝置的管理狀態跟你能不能連到它決定的。

  1. 確認機型通過 Google 認證

    對照Google 官方認證型號清單，精確比對機型名稱與型號。狀態不是「Certified」不要接，客戶會失去 Chrome Education 支援資格。

  2. 確認不是 S 模式

    在裝置上開「設定 → 系統 → 啟用」，確認版本名稱沒有寫「S 模式」。是 S 模式的話 PsExec 用不了，要改走路線 A先退出 S 模式。

  3. 確認是傳統網域、連得到、有帳密

    員工登入用的是傳統公司網域帳號（不是 Microsoft 帳號登入的 Entra ID）；你人在現場、跟這批電腦同一個網段；手上有網域管理員帳密。三項缺一都代表 PsExec 這條路走不下去。

  4. 備妥權杖、Wi-Fi、官方套件

    到對方的 Google Admin Console 產生 ChromeOS Flex 註冊權杖，跟現場網管要 Wi-Fi 名稱密碼，出發前先在公司網路用介面「準備套件」按鈕把約 1GB 的官方套件下載好。完整清單見「開始之前要準備」。

  5. 照 PsExec 路線細節執行

    照「PsExec 路線細節」填裝置清單，介面用網域管理員帳密透過 PsExec 直接連進每一台電腦、推送並執行 agent.exe，按下去立刻跑，不用等 Intune 排程同步。

  6. 先跑 1～2 台模擬測試

    介面上的 dry_run 模式只檢查不動硬碟，綠色橫幅代表過了。整批下去之前不能跳過，詳見「模擬測試與正式部署」。

  7. 正式部署與驗收

    完整現場動線見「現場完整流程」，跑完照「怎麼確認成功」逐台驗收。

兩條路線怎麼判斷的（原理）

什麼時候一定要用 Intune、什麼時候不用，照這裡判斷。

很多人以為這是二選一的偏好題，其實不是。多數情況根本沒得選，是裝置的狀況決定了你只能走哪條。照下面四個問題依序問下去就知道了。

問題一：機型有沒有通過 Google 認證？

沒有就不做，這案子不該接。詳見第 1 章。

問題二：電腦是不是「S 模式」？

這題最容易被忽略，但它會直接決定成敗。

S 模式的電腦，兩條路線都會失敗

微軟官方寫得很清楚：「根據預設，Windows S 模式裝置不允許安裝和執行 Win32 應用程式。」我們要跑的 agent.exe 就是 Win32 程式。

意思是檔案送得過去，但送過去也跑不動。這時候換成 PsExec 也沒用，因為問題不在傳輸方式，在那台電腦根本不准執行這種程式。

Surface Go 出廠預設就是 S 模式，所以這批機器特別要注意。

怎麼看：在那台電腦上開「設定 → 系統 → 啟用」，版本名稱如果寫著「S 模式」就是。

是 S 模式的話，兩個做法：

做法怎麼做評價
退出 S 模式
（建議）		 用 Intune 政策可以整批遠端退出；沒有 Intune 的話每台自己去 Microsoft Store 退出 簡單直接。但是單向的，退出之後回不去 S 模式。反正接下來整台都要變成 ChromeOS Flex 了，這點不構成問題
留在 S 模式，
用 Intune 開例外		 在 Intune 建立「S 模式補充原則」，要用 WDAC 工具做原則、拿去簽章、每個程式還要做目錄檔簽章 非常麻煩，為了一次性的轉換工作不值得。除非客戶資安政策硬性要求留在 S 模式

問題三：這些電腦是被 Intune（Entra ID）管的嗎？

白話講就是：員工登入電腦時，用的是公司的 Microsoft 帳號（像 someone@school.edu.tw），而不是傳統的公司網域帳號。

這種電腦，PsExec 實務上用不了

微軟文件說，只加入 Entra ID 的機器在網路驗證上會被當成「工作群組」電腦，沒有傳統的網域管理員帳號可以用。而 PsExec 正是靠網域管理員帳號連進去的。

所以這種環境只剩 Intune 一條路。這也是 Surface Go 這批機器要用 Intune 的第二個原因。

問題四：你的電腦連得到那些機器嗎？

前面三題都過了，才輪到這題。連得到就可以用 PsExec，連不到就走 Intune。

結論：一張表看完

接案時最先該問的一句話

「你們有沒有 Intune 授權？」Intune 要另外付費，不是每個客戶都有。學校的 Microsoft 365 Education 依方案不同，有的含有的不含。如果對方沒有，而機器又是 S 模式或 Entra ID 環境，那就要先討論怎麼處理，不要到現場才發現卡住。

另一組選擇：下載來源

畫面右上角還有一組「Google 官方／公司鏡像」，那組跟部署方式無關，只是決定那 1 GB 的官方套件去哪裡抓。

選項什麼時候用
Google 官方 預設值，平常都用這個。速度最快，永遠是最新版
公司鏡像 要固定用某個特定版本時用。Google 的檔案會滾動更新，萬一新版有問題，公司鏡像留著已知能正常運作的那份。鏡像還沒建立時這個選項是灰的

選了公司鏡像但連不上時，系統會直接停下來報錯，不會偷偷改用官方版本。因為選鏡像的理由通常就是要那個特定版本，悄悄換成別的版本比直接報錯更糟。

模擬測試與正式部署

這一節是整份文件最重要的部分。

綠色：模擬測試模式

系統只會做檢查（硬碟夠不夠、TPM 狀態、設定檔對不對），不會動硬碟、不會安裝任何東西。可以放心重複跑，這是預設模式。

紅色：正式部署模式

真的執行轉換。裝置的 Windows 與所有資料會被清空，變成 ChromeOS Flex，沒有還原的方法。

怎麼切換

按橫幅右邊的「切換到正式部署」，會跳出確認框，必須手動輸入「確認部署」四個字才切得過去。這是故意設計的麻煩，防止有人手滑點到。

走 PsExec 路線時還有第二道：按下「開始部署」會再問一次「確定要對 N 台裝置執行嗎」，N 是你清單上的實際台數。看清楚那個數字再按。

正確的順序

  1. 綠色模式，一到兩台測試機

    確認連得上、設定檔正確、檢查都通過。

  2. 紅色模式，同樣那一兩台

    真的轉一次，然後去 Admin Console 確認裝置有出現、政策有套用。這步驗的是「整條路走得通」。

  3. 紅色模式，全部裝置

    前面兩步都乾淨才做這步。

現場完整流程

到客戶端那天，照這個順序做。

為什麼不能事先做好安裝包

註冊權杖是包在安裝包裡面的。權杖要現場跟對方拿，所以最終的安裝包一定得現場拿到權杖之後再產生一次。好消息是這步只要幾秒鐘，前提是套件已經先下載好。

  1. 接案時：先查機型有沒有通過認證

    拿對方的機型去對官方認證清單。狀態不是「通過認證」就不要接，這步沒過後面都不用談。

  2. 接案時：確認是不是 S 模式、有沒有 Intune 授權

    請對方隨便找一台開「設定 → 系統 → 啟用」看是不是 S 模式，同時問清楚有沒有 Intune 授權。這兩件事決定整條路怎麼走，見「該走哪條路線」。到現場才發現會很難處理。

  3. 出發前：在公司先按一次「準備套件」

    把 1 GB 的官方檔案抓下來。設定還沒填完會被擋住是正常的，這步的目的只是下載。

  4. 到現場：跟對方索取註冊權杖

    請對方的 Google 管理員到 Admin Console 產生，路徑在「開始之前要準備」那張表裡。

  5. 填三個欄位並儲存

    註冊權杖、Wi-Fi 名稱、Wi-Fi 密碼。保持綠色的模擬測試模式。

  6. 對一兩台測試機跑模擬測試

    看記錄區有沒有錯誤訊息。有錯先解決，不要往下走。

  7. 切成紅色，同樣那一兩台跑真的

    裝置會在兩分鐘內顯示安裝通知並重新開機。等它跑完進入 ChromeOS Flex 設定畫面。

  8. 去 Admin Console 確認註冊成功

    裝置 → ChromeOS，看新機器有沒有出現在正確的組織單位裡、政策有沒有套用。

  9. 全部沒問題，才擴大到所有裝置

    Intune 路線就把指派對象改成全部；PsExec 路線就把裝置清單填完整。

Intune 路線細節

產生安裝包之後，要在 Intune 後台做的設定。

介面按下「開始產生安裝包」後，會在 output\ 產出一個約 1 GB 的 .intunewin 檔案，畫面上會出現下載連結。接著到 Intune 後台：

  1. 新增 Win32 應用程式

    應用程式 → Windows → 新增 → Win32 應用程式，上傳那個 .intunewin。

  2. 安裝命令填 agent.exe

    要用系統管理員權限執行。

  3. 偵測規則填「agent.log 檔案存在」

    這條規則只是為了滿足 Intune 介面的必填要求。裝置轉完 ChromeOS 之後就不再是可偵測的 Windows 軟體狀態了，所以本機偵測沒有實質意義，真正的成功判斷是回 Admin Console 看，這也是 Google 官方文件的建議。

  4. 指派對象先選測試群組

    先指派給那一兩台測試機。確認整條路走得通，再回來改成全部裝置。

Intune 不會立刻執行

派送時間由 Intune 的同步排程決定，可能要等一段時間裝置才收到。這是正常的，不是失敗。急著要立刻執行請改走 PsExec 路線。

PsExec 路線細節

不靠任何管理系統，直接對一份清單動手。

裝置清單怎麼填

表格一行一台，填電腦名稱或 IP。可以直接從 Excel 整欄複製後貼上，系統會自動展開成多列，跟 CEU 綁定系統的操作方式一樣。

帳號密碼

兩個欄位留空的話，會用你目前登入這台電腦的帳號權限去連。前提是那個帳號在所有目標裝置上都有系統管理員權限。不是的話就填一組有權限的網域管理員帳密。

同時處理幾台

預設 5 台。數字調大速度快但網路負擔重，一般不用超過 10。

系統實際做的事

對清單上每一台裝置，依序做四個動作：連上對方的管理共用資料夾、把整包 FRD 套件複製過去、用 PsExec 遠端執行 agent.exe、斷開連線。任何一步失敗都會記在該台的結果裡，不會影響其他台繼續跑。

跑完的報告

畫面上會即時顯示成功與失敗台數，全部跑完可以下載 CSV 報告，裡面有每一台的詳細結果，用 Excel 打開就能看。

連不上通常是防火牆

PsExec 需要對方裝置開放檔案分享（445 埠）與管理共用資料夾。企業防火牆或裝置本機防火牆擋掉的話就會連不上。先拿一台測試確認通得過，再排整批。

怎麼確認成功

「程式跑完沒報錯」不等於「部署成功」。

Google 官方明確建議：用 Admin Console 或 Directory API 確認裝置有沒有註冊進來，不要只看本機記錄。因為裝置轉完之後已經不是 Windows 了，本機那邊能給的資訊很有限。

要看的地方看什麼
裝置畫面 兩分鐘內出現安裝通知並重開機，重開後進入 ChromeOS Flex 的安裝流程
Google Admin Console 裝置 → ChromeOS，新機器有出現、在正確的組織單位、政策有套用。這是最終判準
agent.log 失敗時查原因用。模擬測試會留下 InstallSkipped 記錄，代表檢查通過但依設定沒有真的安裝

關於 agent.log

這個記錄檔不是 agent.exe 自己寫的，是系統一併帶上去的記錄器產生的。遠端部署沒有螢幕可看，沒有這個檔案就等於瞎子，所以預設一定會帶。

照實際會遇到的狀況排的。

執行按鈕是灰的 三個設定欄位沒填完。填好按「儲存設定」就會解鎖

連得到但複製檔案失敗 多半是權限或防火牆。確認帳號在對方機器上是系統管理員，以及 445 埠沒被擋

給技術人員：指令列

網頁介面能做的事，指令列都能做，兩者共用同一套邏輯。

設定檔在 secrets\config.json，欄位跟介面上的一樣。

產生 Intune 安裝包

python intune_flex_packager.py

PsExec 大量部署

python psexec_mass_deploy.py --parallel 5

裝置清單讀 secrets\devices.txt，一行一台，# 開頭是註解。設定檔裡 dry_run 是 false 時，必須額外加 --yes 才會真的執行，防止手滑。

建立公司鏡像

python mirror_to_r2.py --check   # 先驗憑證
python mirror_to_r2.py           # 實際上傳

需要 Cloudflare R2 的憑證，設定方式寫在那支程式開頭。

名詞解釋

文件裡出現過的技術名詞，一句話版本。

FRD
ChromeOS Flex Remote Deployment，Google 官方的遠端部署套件，核心是 agent.exe 這支程式。
授權池
組織帳號裡購買好、還沒指派給裝置的授權額度。買授權是先囤在池子裡，裝置註冊時才從池子扣一個名額，這兩件事分開發生。
註冊權杖
Enrollment Token。一串代碼，讓裝置轉完之後知道要自動加入哪個單位的 Google Admin Console。等同密碼等級的機密。
Intune
微軟的裝置管理雲端服務。企業用來遠端管理員工電腦、派送軟體。要另外付費，不是每個客戶都有。
S 模式
Windows 的一種鎖定狀態，只准跑 Microsoft Store 的程式，不准跑一般的 .exe。Surface Go 出廠預設就是。退出是單向的，退了回不去。
Win32 應用程式
就是一般的 Windows 程式（.exe 那種）。agent.exe 屬於這一類，所以在 S 模式下跑不動。
Entra ID
微軟的雲端帳號系統，舊名 Azure AD。電腦「加入 Entra ID」之後，員工用公司的 Microsoft 帳號登入，跟傳統的公司網域不同。這種電腦沒有網域管理員帳號，所以 PsExec 用不了。
PsExec
微軟 Sysinternals 出的工具，可以在遠端的 Windows 電腦上執行程式，IT 界的常見工具。
SMB / 445 埠
Windows 的檔案分享機制與它使用的網路埠。PsExec 靠它把檔案送過去，被防火牆擋住就會連不上。
模擬測試
Dry run。只跑檢查不做實際變更的模式，用來確認流程正確。
TPM
電腦主機板上的安全晶片，存放加密金鑰。轉換系統時要清除它，原本 Windows 的加密資料也就跟著失效。
ONC
Open Network Configuration，ChromeOS 用的網路設定格式。Wi-Fi 的名稱與密碼就是寫在這種檔案裡。
.intunewin
Intune 專用的軟體封裝格式。把要派送的檔案打包成這種格式才能上傳到 Intune 後台。
