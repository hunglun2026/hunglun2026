ChromeOS Flex 遠端部署：完整使用說明

從接案、檢查機器、設定、選路線、部署到驗收，一份看完。涵蓋「沒有 Intune」「沒有 CEU」這些情況。

0這份說明怎麼讀

第一次接觸的人照順序讀完；已經熟的人直接跳到要的章節。

第 1～3 章弄懂原理、判斷客戶狀況
第 4～7 章檢查機器能不能轉
第 8～10 章準備工具、填設定
第 11～17 章選路線、照步驟部署
第 18～22 章驗收、排錯、速查

標記說明：

  • 已實測 我們自己跑過、確認可行
  • 未實測 照官方文件或工具文件寫的，還沒在真實機器上跑過，第一次用請先拿一台測
整份說明最重要的一句話
正式部署會清空整台電腦的 Windows 與所有資料，救不回來。任何情況都先用「模擬測試」跑一兩台，沒問題才動真的。

1先搞懂：做事的程式 vs 送貨方式

很多混亂都來自把這兩層當成同一件事。

層是什麼會不會換
做事的程式Google 官方的 FRD 套件：agent.exe ＋ agent.toml（設定）＋ wifi.onc（Wi-Fi）。在 Windows 上執行後，它會清除 TPM、重新分割硬碟、安裝 ChromeOS Flex、連上 Wi-Fi，有權杖的話再自動註冊永遠是同一支，不會換
送貨方式把上面那包東西送到每台電腦並按下執行：Intune、PsExec、Tailscale＋PsExec、Action1、自己雙擊有很多種，哪條走不通就換一條

所以「沒有 Intune」只代表少了一條送貨路線，FRD 照樣能用。這份說明第 11 章會帶你挑一條走得通的路線。

FRD 套件不用等 Google 回信
官方套件可以直接下載：https://dl.google.com/cros-frd/frd-latest.zip（約 1GB）。填表單只會收到部署指南的入口信，跟能不能下載無關。工具介面右上角的「準備套件」按鈕就是在下載這個檔案。

2Intune、CEU 有或沒有的四種組合

Intune 屬於 Windows 這一端，CEU 屬於 ChromeOS 這一端，兩件事互不相干。

管哪一端缺了會怎樣有沒有免費替代
IntuneWindows：把 agent.exe 送過去執行換別條路線送有 PsExec、Action1（前 200 台免費）、自助執行
CEU
Chrome Education Upgrade		ChromeOS：轉完後註冊進 Google Admin Console 被集中管理轉完是「未受管」的 Flex沒有 只能購買。企業版 Chrome Enterprise Upgrade 有 30 天 50 台試用，教育版沒有試用

四種組合怎麼做

IntuneCEU做法結果
有有路線 E（Intune），填權杖自動註冊、集中管理，最完整
沒有有路線 A～D 擇一，填權杖跟上面一樣自動註冊，只是送貨方式不同
有沒有路線 E，勾「不註冊」未受管 Flex
沒有沒有路線 A～D 擇一，勾「不註冊」未受管 Flex

「未受管」的 Flex 代表什麼

官方說明 enrollment_token 是選填：「權杖未定義或空白時，會安裝 ChromeOS Flex，但裝置不會自動註冊。」所以沒有 CEU 也能轉，但要讓客戶知道：

  • 不會出現在 Google Admin Console，沒辦法統一派送政策、App、設定
  • 任何人都能用個人 Google 帳號登入，沒辦法限定只用學校或公司帳號
  • 遺失或被偷時沒辦法遠端停用
  • 之後買了 CEU，沒辦法遠端補註冊，只能到現場一台一台註冊或重灌（第 19 章）
交件前一定要講
客戶以為「轉成 Chromebook 就能像學校其他 Chromebook 一樣管」，結果拿到的是未受管的機器，這是最常見的糾紛來源。要不要買 CEU，在報價階段就說清楚。

3接案時要問客戶的問題

照順序問，每一題的答案都會影響後面怎麼做。

  1. 電腦的廠牌和型號是什麼？有幾台？ → 拿去比對 Google 認證清單（第 4 章）。沒通過認證就不接
  2. 轉完要不要集中管理？有沒有買 CEU，還剩幾個名額？ → 決定要填權杖還是勾「不註冊」（第 9 章）
  3. 有沒有 Intune 授權？這些電腦有被 Intune 管嗎？ → 有就可以走路線 E
  4. 電腦是 Windows 10 還是 11？是不是 S 模式？（Surface Go 出廠預設是 S 模式）→ 第 7 章
  5. 電腦都在同一個地方嗎？我們能到現場嗎？ → 決定路線 A 或 C、D
  6. 電腦登入用的是網域帳號、Microsoft 帳號，還是本機帳號？有沒有每台都能用的系統管理員帳號和密碼？ → PsExec 需要
  7. 轉完要連哪個 Wi-Fi？是一般密碼型（WPA2 個人），還是要帳號密碼的企業型（802.1X）？ → 本工具目前只支援一般密碼型
  8. 電腦裡的資料備份了嗎？ → 轉了就全部清空，請客戶書面確認已備份

4機器要符合的條件

前五項是 Google 官方的硬性門檻，第六項是我們的商用紅線。

#條件怎麼看
1開機模式是 UEFI（不能是 Legacy BIOS）預檢的「開機模式」欄，或 msinfo32 的「BIOS 模式」
2系統磁碟是 GPT 格式預檢的「磁碟格式」欄
3磁碟 32GB 以上，至少 5GB 可用空間預檢的「磁碟GB」「可用GB」欄
4作業系統是 Windows 10 或 11預檢的「作業系統」欄
5有網路（有線或 Wi-Fi）轉完要靠網路下載更新、註冊
6型號在 Google 認證清單上，狀態是「通過認證」預檢的「廠牌型號」欄拿去人工比對

認證清單四種狀態

狀態我們的做法
通過認證可以接，唯一建議的狀態
預期會出現輕微問題先跟客戶講清楚風險、實測過再決定
預期會出現重大問題不做
取消認證不做

沒列在清單上的機型，Google 官方說「裝置如果未列在認證裝置清單中，就不適用 Chrome Education 或 Chrome Enterprise 支援服務」。客戶付錢買了 CEU，裝在未認證機器上等於放棄支援資格，所以不接。清單更新頻繁，每次接案都重新查。

TPM 不用自己處理
官方提到部分機型要先清除 TPM，FRD 會自己處理。預檢表的 TPM 欄只是參考。

5部署前預檢（單台／大量）

只讀取資訊，不改任何設定，可以放心跑。接案第一步就先跑，不合格的機器提早挑出來。

方法一：單台，在那台電腦上直接跑 已實測

  1. 把 precheck.ps1 複製到那台電腦，例如放在桌面
  2. 用系統管理員身分開 PowerShell：開始按鈕按右鍵 →「終端機（系統管理員）」或「Windows PowerShell（系統管理員）」
  3. 執行（路徑換成你放的位置）： 
    powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Desktop\precheck.ps1"
  4. 看結果：最後一行會寫「結果：硬體條件合格」（綠字）或「結果：不合格」（紅字）並列出原因

輸出範例：

電腦名稱   : HUNGLUN-STEVE
廠牌型號   : ASUSTeK COMPUTER INC. E500A_WS770T
作業系統   : Microsoft Windows 11 專業版
開機模式   : UEFI
磁碟格式   : GPT
磁碟大小GB : 477
可用空間GB : 268.7
TPM        : 有

結果：硬體條件合格
最後一步要人工做：拿「廠牌型號」去 Google 認證清單比對
不要用記事本另存 precheck.ps1
這個檔案存成「UTF-8 含 BOM」格式，Windows 內建的 PowerShell 才讀得懂裡面的中文。用記事本改過再存成別的編碼，會出現一堆紅字語法錯誤。壞了就重新從工具資料夾複製一份。

方法二：不用檔案，看系統資訊 已實測

  • 開機模式：Win+R → 輸入 msinfo32 → 看「BIOS 模式」：UEFI 才可以，「舊版」就是 Legacy
  • 磁碟格式：開始按鈕按右鍵 →「磁碟管理」→ 在「磁碟 0」按右鍵 →「內容」→「磁碟區」分頁 → 看「磁碟分割樣式」要是 GPT

方法三：大量，從你的電腦一次查全部 已實測（本機）

需要跟 PsExec 路線一樣的前置條件（第 12 章的「目標電腦要先做的事」）。目前只有指令列版本，要裝 Python 與 openpyxl 套件。

  1. 填裝置清單 secrets\devices.txt：一行一台，填電腦名稱或 IP，# 開頭是註解
  2. 填帳號密碼：secrets\config.json 的 remote_admin_user、remote_admin_password。預檢不需要權杖和 Wi-Fi
  3. 在工具資料夾執行： 
    python psexec_mass_deploy.py --precheck
  4. 打開報表：output\precheck-時間.xlsx

報表怎麼看

結果欄意思下一步
合格（綠）五項硬體條件都過了拿「廠牌型號」比對認證清單，把狀態填在「認證清單狀態（人工填）」欄
不合格（紅）「不合格原因」欄寫了哪幾項沒過UEFI／GPT 看第 6 章；空間不足請客戶清理；不是 Win10/11 就不做
連不上（黃）連線或執行失敗，「不合格原因」欄有錯誤訊息看第 20 章對照錯誤訊息

報表含客戶的電腦名稱與型號清單，已設定不會進公開版本庫，交給客戶以外的人前先確認。

6不是 UEFI 怎麼辦

先知道一件事：Windows 11 的機器一定是 UEFI（這是安裝 Windows 11 的門檻），只有 Windows 10 舊機可能需要處理。

UEFI 是電腦開機後、Windows 啟動之前先跑的那層韌體，負責檢查硬體再把作業系統叫起來，取代舊的 Legacy BIOS。UEFI 搭配 GPT 磁碟，Legacy 搭配 MBR 磁碟，兩組要配對。FRD 要在磁碟上另外切出 Flex 的開機區，只支援 UEFI＋GPT。

先想想值不值得
還是 Legacy 的機器通常很舊，很少在 Google 認證清單上。先比對認證清單，沒通過就直接排除，不用花時間轉換。

轉換步驟（順序不能顛倒，不然 Windows 開不了機）

  1. 先備份：轉換磁碟格式一般不會清資料，但萬一失敗會開不了機
  2. 在 Windows 裡把磁碟轉成 GPT（系統管理員身分開命令提示字元，可以遠端做）： 
    mbr2gpt /validate /allowFullOS
mbr2gpt /convert /allowFullOS
    第一行只檢查，顯示 Validation completed successfully 才跑第二行。
    若有開 BitLocker，轉換前先暫停：manage-bde -protectors -disable C:
  3. 重開機，進韌體設定畫面：開機時連按下表的按鍵（各機型可能不同，以廠商說明為準）
    廠牌常見按鍵
    DellF2
    HPF10（或 Esc 再選）
    LenovoF1 或 F2（筆電有時要按 Fn）
    ASUS、AcerF2 或 Del
    Surface按住音量＋再按電源
  4. 改開機模式：找 Boot Mode、Boot List Option 這類選項，改成「UEFI」；有「CSM」或「Legacy Support」就關掉
  5. 存檔重開機，進 Windows 後再跑一次預檢確認

想遠端切開機模式：只有部分商用機種的廠商工具做得到，例如 Dell Command | Configure、HP BIOS Configuration Utility、Lenovo 的 WMI BIOS 設定。家用機種多半只能到現場一台一台切。

7S 模式怎麼辦

S 模式的 Windows 不准執行一般的 Windows 程式（Win32），agent.exe 就是這種程式，連 PowerShell 也不能用。

  • 怎麼看：設定 → 系統 → 啟用，版本名稱寫著「S 模式」就是。Surface Go 出廠預設是 S 模式
  • 預檢會怎樣：S 模式的機器跑不了預檢腳本，大量預檢會顯示「連不上：腳本沒產生結果」
  • 處理：退出 S 模式。有 Intune 可以用政策整批退出；沒有的話，每台到 Microsoft Store 搜尋「退出 S 模式」手動退出（要登入 Microsoft 帳號，免費）
  • 注意：退出是單向的，退了回不去。反正接下來整台都要變成 Flex，這點不構成問題

8要準備的工具與帳號

你這邊（操作端電腦）

東西用途怎麼拿
本工具（flex-deploy-tool）網頁操作介面、產生設定、大量部署雙擊 開始操作.bat 開介面
FRD 官方套件（約 1GB）真正做事的 agent.exe 與 Flex 映像檔介面右上角「準備套件」，或直接下載 frd-latest.zip
PsExec路線 A、B 用來遠端執行微軟官方工具，第一次執行時自動下載
Python ＋ openpyxl只有指令列（大量預檢）需要pip install openpyxl
Tailscale只有路線 B 需要tailscale.com，免費方案有台數上限，以官網為準
Action1 帳號只有路線 C 需要action1.com，前 200 台永久免費

向客戶拿

  • 機型清單、電腦名稱或 IP 清單
  • 每台都能用的系統管理員帳號密碼（路線 A、B 需要）
  • 轉完要連的 Wi-Fi 名稱與密碼（一般密碼型）
  • 註冊權杖（有 CEU 才需要，第 9 章），或書面確認「不註冊」
  • 資料已備份的書面確認

9註冊權杖（或選擇不註冊）

有 CEU：拿權杖

  1. 請客戶的 Google 管理員登入 admin.google.com
  2. 路徑：裝置 → Chrome → 註冊權杖 → 註冊 → 選「非 ChromeOS 裝置（採用 ChromeOS Flex）」→ 自動註冊
  3. 選好組織單位：權杖綁的是組織單位，轉完的機器會進到這個單位
  4. 複製權杖，貼到工具介面的「註冊權杖」欄
權杖不用等裝置存在
權杖是綁在組織單位上的通用碼，任何裝置都還沒出現就可以先產生。真正的前提是授權池裡還有足夠的 CEU 名額，裝置註冊那一刻才會扣一個。
權杖是機密
拿到權杖的人可以把任何機器註冊進客戶的組織，不要貼到聊天群組或 email。

沒有 CEU：勾「不註冊」

工具介面「註冊權杖」欄下方有一個勾選框「客戶沒買 CEU，不註冊（轉成未受管 Flex）」。勾了以後：

  • 權杖欄會變灰，不用填
  • 畫面出現紅色警告框，提醒轉完是未受管的機器
  • 產生的 agent.toml 不會寫入權杖，FRD 照樣安裝 Flex，只是不註冊
  • 執行時記錄區會再印一次警告
為什麼要打勾，不是留空就好
如果「權杖留空」就自動放行，現場趕時間忘了貼權杖，幾十台機器轉完才發現都沒註冊，只能一台一台補。所以設計成必須明確勾選，沒勾又沒填，執行按鈕會鎖住。

10填設定：介面與設定檔

用網頁介面（建議）

  1. 雙擊 開始操作.bat，瀏覽器會自動打開操作畫面（只有這台電腦連得到）
  2. 輸入系統密碼（跟 Steve 拿，不寫在文件裡）
  3. 右上角按「準備套件」，等進度條跑完，顯示「套件已就緒」。出發前在公司網路先做，現場網路可能很慢
  4. 填「部署設定」：註冊權杖（或勾不註冊）、Wi-Fi 名稱、Wi-Fi 密碼，按「儲存設定」
  5. 確認上方橫幅是綠色「模擬測試模式」

密碼類欄位存過之後會顯示「已設定（要改才需重打）」，不會把明碼顯示回來。要改就整個重打。

右上角的「Google 官方／公司鏡像」跟部署方式無關
只是決定那 1GB 套件去哪裡下載。平常用「Google 官方」（預設，永遠是最新版）。「公司鏡像」是要固定用某個已知可用的版本時才選，鏡像還沒建立時按不下去；選了鏡像但連不上，系統會直接報錯停下來，不會偷偷改用官方版本。
為什麼最終的安裝包要在現場產生
註冊權杖是包在安裝包裡的，權杖通常到現場才跟客戶拿，所以最終版一定是拿到權杖之後再產生一次。只要套件已經先下載好，這步只要幾秒鐘。

用設定檔（指令列）

檔案位置 secrets\config.json，第一次從 secrets\config.example.json 複製。

欄位必填說明
enrollment_token有 CEU 時必填註冊權杖
no_enrollmenttrue＝不註冊，權杖可以不填。預設 false
wifi_ssid必填Wi-Fi 名稱
wifi_password必填Wi-Fi 密碼（目前只支援 WPA／WPA2 個人型）
dry_runtrue＝模擬測試（預設），false＝正式部署，不可逆
remote_admin_userPsExec 用目標電腦的系統管理員帳號。留空就用你目前登入的帳號
remote_admin_passwordPsExec 用上面帳號的密碼
enable_logging是否用 Vector 把執行記錄存成 agent.log，建議 true
download_sourceofficial（Google 官方，預設）或 r2（公司鏡像）

欄位值如果還是「【待填】」「貼 ...」「TEST-」開頭，工具會當成沒填，擋下來不讓執行。

11選送貨路線

照順序問自己，第一個「是」就是你的路線。

  1. 電腦有被 Intune 管，而且授權有效？ → 路線 E：Intune
  2. 電腦跟你在同一個網路（同一個 Wi-Fi 或路由器），而且有每台的系統管理員帳密？ → 路線 A：PsExec
  3. 電腦分散各地，但能請對方幫忙裝一個小程式？ → 路線 C：Action1（推薦），或路線 B：Tailscale＋PsExec
  4. 台數少、你連不到、對方願意自己操作？ → 路線 D：自助執行
路線需要同網路要先在每台裝東西要帳密適合狀態
A PsExec要不用裝軟體，改設定＋開防火牆要電腦集中在一間教室或辦公室本機已實測
B Tailscale＋PsExec不用Tailscale要分散各地、不想用管理平台未實測
C Action1不用Action1 代理程式不用分散各地、台數多未實測
D 自助執行不用不用對方自己有幾台、對方願意自己動手未實測
E Intune不用不用（已被管）不用已經有 Intune第 16 章

12路線 A：PsExec（同網段）

從你的電腦直接連進每一台目標電腦，複製套件過去並執行。按下去就跑，不用等任何排程。

目標電腦要先做的事（每台一次）

  1. 確認有系統管理員帳號，而且每台的帳號密碼一樣最方便（不一樣也可以，要分批跑）
  2. 非網域電腦（個人電腦、工作群組、只加入 Entra ID）要解除遠端限制：用系統管理員身分開命令提示字元，執行 
    reg add HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System /v LocalAccountTokenFilterPolicy /t REG_DWORD /d 1 /f
    不做這步，非內建 Administrator 的管理員帳號從遠端連進來一律「拒絕存取」。傳統網域電腦用網域管理員帳號就不需要
  3. 開防火牆的「檔案及印表機共用」：控制台 → Windows Defender 防火牆 → 允許應用程式通過防火牆 → 勾「檔案及印表機共用」的「私人」。網路設定檔也要設成「私人網路」

網路條件

  • 你的電腦跟目標電腦在同一個網段（同一個 Wi-Fi 或接同一台路由器）
  • Wi-Fi 不能開「AP 隔離」（訪客網路常常有開），開了電腦之間互相看不到
  • 中間不能有防火牆擋 445 埠（檔案分享用的）

操作步驟（網頁介面）

  1. 先跑預檢（第 5 章方法三），確認每台都「合格」，型號也比對過
  2. 填設定、確認綠色模擬模式（第 10 章）
  3. 切到「直接遠端部署（PsExec）」分頁
  4. 貼裝置清單：可以從 Excel 整欄複製貼上，一行一台
  5. 填系統管理員帳號密碼，同時處理台數先用預設 5
  6. 按執行，看記錄區每台的結果；跑完可以下載報告

操作步驟（指令列）

python psexec_mass_deploy.py                    # 模擬測試（dry_run=true）
python psexec_mass_deploy.py --parallel 10      # 同時處理 10 台
python psexec_mass_deploy.py --yes              # dry_run=false 時必須加，才會真的轉

系統實際做的事（每台）

  1. 用帳密連到那台電腦的 C$ 管理共用
  2. 把整個 FRD 套件（含 agent.toml、wifi.onc）複製到那台電腦的 C:\ProgramData\frd-deploy
  3. 用 PsExec 遠端執行 agent.exe（不等它跑完，因為正式部署會重開機）
  4. 中斷連線

套件約 1GB，同時處理 5 台就是同時傳 5GB，現場網路慢的話把同時台數調低。

13路線 B：Tailscale ＋ PsExec 未實測

用 Tailscale 把分散各地的電腦接成同一個虛擬網路，之後就跟路線 A 一模一樣。

  1. 建一個 Tailscale 帳號（tailscale.com），你的電腦先裝好並登入
  2. 每台目標電腦裝 Tailscale，登入同一個帳號（或用邀請、授權金鑰加入）
  3. 在 Tailscale 後台看到每台電腦的 100.x.x.x 位址
  4. 每台目標電腦做路線 A 的「目標電腦要先做的事」。防火牆的「檔案及印表機共用」要允許 Tailscale 那張網卡
  5. 裝置清單填 100.x.x.x 位址，照路線 A 執行
要注意
透過網際網路傳 1GB 套件會很慢，而且轉完 Flex 之後 Tailscale 就不見了。先拿一台測通再整批做。

14路線 C：Action1（分散各地） 未實測

Action1 是雲端遠端管理平台，前 200 台永久免費、功能不設限。每台裝一次代理程式之後，就能從網頁後台派送指令碼，用法跟 Intune 很像。

準備

  1. 註冊 Action1（action1.com 的 Free Edition）
  2. 在後台下載代理程式安裝檔，請客戶在每台目標電腦安裝（一次性），或用現場隨身碟裝
  3. 確認每台電腦都出現在 Action1 後台
  4. 先用 Action1 的「執行指令碼」功能，把 precheck.ps1 的內容派送給全部電腦，從結果看哪些合格

派送 FRD 的指令碼範本

讓每台電腦自己從 Google 下載套件、寫入設定、執行。用 Action1 的「執行指令碼」，以系統權限執行。把三個 【】 換成實際值（不註冊就把權杖那行整行刪掉）：

PowerShell（先 dry_run = true 測一台）
$dir = "C:\ProgramData\frd-deploy"
New-Item -ItemType Directory -Force -Path $dir | Out-Null
$zip = "$dir\frd.zip"
Invoke-WebRequest "https://dl.google.com/cros-frd/frd-latest.zip" -OutFile $zip -UseBasicParsing
Expand-Archive $zip -DestinationPath $dir -Force
Remove-Item $zip

@"
data_dir = 'install'
dry_run = true
enrollment_token = '【註冊權杖】'
onc_file = 'wifi.onc'
verbose_boot = false
"@ | Set-Content "$dir\agent.toml" -Encoding ASCII

@"
{"Type":"UnencryptedConfiguration","NetworkConfigurations":[{"GUID":"{$([guid]::NewGuid())}","Name":"【Wi-Fi 名稱】","Type":"WiFi","WiFi":{"Passphrase":"【Wi-Fi 密碼】","SSID":"【Wi-Fi 名稱】","Security":"WPA-PSK","AutoConnect":true}}]}
"@ | ForEach-Object { [IO.File]::WriteAllText("$dir\wifi.onc", $_) }   # UTF-8 不帶 BOM

Set-Location $dir
.\agent.exe
這段範本還沒實測，第一次一定先這樣做
  • 保持 dry_run = true，只派給一台，從 Action1 的執行結果確認 agent.exe 有跑起來、沒有錯誤
  • Wi-Fi 名稱或密碼含 " 或 \ 這類符號時，JSON 會壞掉，改用本工具產生的 wifi.onc 內容貼上
  • 每台都會各自下載 1GB，同一地點很多台時注意頻寬
  • 權杖與 Wi-Fi 密碼會留在 Action1 後台的指令碼紀錄裡，用完記得刪

15路線 D：自助執行 未實測

把設定好的套件交給對方，對方在自己的電腦上執行。適合台數少、你連不到的情況。

  1. 在你的電腦用工具介面填好設定並跑過一次模擬測試，讓 tools\frd-package\ 裡的 agent.toml、wifi.onc 產生好
  2. 把整個 tools\frd-package 資料夾（約 1GB）用隨身碟或雲端硬碟交給對方。裡面含權杖與 Wi-Fi 密碼，不要放公開連結
  3. 對方把資料夾放到 C:\frd-deploy
  4. 對方用系統管理員身分開命令提示字元，執行： 
    cd /d C:\frd-deploy
agent.exe
  5. 模擬測試沒問題後，把 agent.toml 裡的 dry_run = true 改成 false 再執行一次，電腦會重開機開始轉換

如果對方電腦也能跑本工具，也可以讓對方直接雙擊 開始操作.bat，在 PsExec 分頁的裝置清單填自己的電腦名稱。

16路線 E：Intune

電腦已經被 Intune 管、授權有效時用。裝置自己向雲端報到，把套件拉下來安裝，不用人在現場，也不用帳密。

  1. 產生安裝包：工具介面切到「產生 Intune 安裝包」分頁，按「開始產生安裝包」。會在 output\ 產出約 1GB 的 .intunewin，畫面上有下載連結。指令列是 python intune_flex_packager.py
  2. 新增 Win32 應用程式：Intune 後台 → 應用程式 → Windows → 新增 → Win32 應用程式，上傳那個 .intunewin
  3. 安裝命令填 agent.exe，用系統權限執行
  4. 偵測規則填「agent.log 檔案存在」：這條只是滿足 Intune 介面的必填要求。裝置轉完 Flex 就不再是 Windows，本機偵測沒有實質意義，真正的成功判斷是回 Admin Console 看，這也是 Google 官方的建議
  5. 指派對象先選測試群組（一兩台），整條路走通了再改成全部裝置
Intune 不會立刻執行
派送時間由 Intune 的同步排程決定，可能要等一段時間裝置才收到，這是正常的。急著要立刻執行就改走路線 A。
S 模式的電腦
Intune 可以用政策整批讓電腦退出 S 模式，這是沒有 Intune 時做不到的。先退出 S 模式，再派送 FRD（第 7 章）。
只加入 Entra ID 的電腦也不一定要走 Intune
這種電腦在網路驗證上被當成工作群組電腦，沒有網域管理員帳號可用。但如果每台有本機系統管理員帳號，做完第 12 章的 LocalAccountTokenFilterPolicy 設定，PsExec 照樣能用；沒有本機管理員帳號，就走 Action1 或自助執行。

17模擬測試到正式部署的順序

不管走哪條路線都一樣，這個順序不能跳。

模式做什麼
綠色：模擬測試只檢查（硬碟夠不夠、TPM 狀態、設定檔對不對），不動硬碟、不安裝任何東西，可以放心重複跑。這是預設模式
紅色：正式部署真的轉換。Windows 與所有資料清空，沒有還原的方法

介面上的兩道關卡：按橫幅右邊「切換到正式部署」後，必須手動輸入「確認部署」四個字才切得過去；走 PsExec 時按下開始部署，還會再問一次「確定要對 N 台裝置執行嗎」，看清楚那個台數再按。指令列則是 dry_run 改 false 之後，沒加 --yes 會被擋下來。

  1. 綠色模擬模式，一到兩台測試機：看記錄區有沒有錯誤；目標電腦的 C:\ProgramData\frd-deploy\agent.log 出現 InstallSkipped，代表檢查都過了，只是因為模擬模式沒安裝
  2. 紅色正式模式，同樣那一兩台：電腦會重開機開始轉換，花多久依機器與網路而定，過程中不要關機
  3. 驗收那一兩台（第 18 章）。這步驗的是「整條路走得通」
  4. 都沒問題，才擴大到全部電腦：Intune 把指派對象改成全部；PsExec 把裝置清單填完整
正式模式之前再確認一次
裝置清單只有你要轉的電腦？客戶的資料備份了？權杖是正確組織的，或確定不註冊？Wi-Fi 名稱密碼對嗎？

18驗收

「程式跑完沒報錯」不等於部署成功。Google 官方建議用 Admin Console 或 Directory API 確認裝置有沒有註冊進來，不要只看本機記錄，因為轉完之後已經不是 Windows，本機能給的資訊很有限。

每台都要看

  • 開機進得了 ChromeOS Flex 畫面
  • 自動連上指定的 Wi-Fi
  • 設定 → 關於 ChromeOS 看得到版本號，可以檢查更新

有註冊的再多看（最終判準）

  • 登入畫面下方顯示「這部裝置由 某某組織 管理」
  • Google Admin Console → 裝置 → Chrome → 裝置，看得到這台，而且在正確的組織單位、政策有套用
  • CEU 授權使用數有增加

沒註冊的

  • 開機到歡迎畫面，可以用任何 Google 帳號登入
  • 交件時把「未受管代表什麼」（第 2 章）再跟客戶講一次，最好書面確認

agent.log 是失敗時查原因用的。它不是 agent.exe 自己寫的，是工具一併帶上去的記錄器（Vector）產生的，所以 enable_logging 建議保持開啟。

19已經是未受管 Flex，之後才要註冊 CEU

先講結論：已經裝好的未受管 Flex，沒有任何辦法從遠端大量註冊。CEU 的遠端大量註冊，只能在「還是 Windows 的時候」用 FRD 帶權杖一次做完。

為什麼遠端做不到（官方依據）

  • ChromeOS Flex 不支援零接觸註冊，也不支援強制重新註冊（官方「ChromeOS Flex 與 ChromeOS 的差異」頁）
  • 未受管的 Flex 上沒有任何可以遠端派送指令的管道：沒有 Intune、沒有 PsExec，也裝不了 Action1 這類代理程式
  • 官方註冊頁：「您必須在任何人登入裝置前先註冊這些裝置。如果有人在您註冊前就先行登入，您就必須先抹除裝置資料再重新註冊」

所以真正的「遠端大量部署 CEU」是這樣做

在 FRD 那一步就填權杖
客戶買好 CEU、拿到註冊權杖，在第 9 章填進去（不要勾「不註冊」）。FRD 轉 Flex 的同時就自動註冊、自動從授權池扣名額，全程遠端。這是唯一的遠端大量做法，所以 CEU 要在轉機之前就買好。

已經轉好的機器，三種補救做法

做法要不要到現場會不會清資料適合
A. 一台一台手動註冊（Ctrl+Alt+E）要，每台幾分鐘沒人登入過的不會；有人登入過要先 Powerwash，會清台數少
B. 用帶權杖的 USB 安裝碟重灌要，每台插一次隨身碟會（等於重灌）台數多、想讓開機後自動註冊、不用每台輸入帳密
C. 用帶權杖的映像檔走網路開機（PXE）重灌每台要設定從網路開機會（等於重灌）有 IT 人員、有 PXE 環境的大型場域

做法 A：一台一台手動註冊 未實測

  1. 確認授權池有足夠名額
  2. 如果已經有人登入過這台：先 Powerwash（恢復原廠設定）。登入畫面按 Ctrl+Alt+Shift+R，照畫面重新啟動並確認。會清掉本機資料
  3. 在登入畫面（還沒有人登入之前）按 Ctrl+Alt+E，進入企業註冊畫面
  4. 用客戶的管理員帳號，或被允許註冊裝置的帳號登入，完成註冊。不想把管理員密碼交給現場人員的話，請客戶在 Admin Console 的註冊權限設定裡，開放一個專用帳號可以註冊裝置
  5. 到 Admin Console 確認這台出現，移到正確的組織單位

做法 B、C：把權杖封進 Flex 映像檔再重灌 未實測

官方「自動註冊 ChromeOS Flex 裝置」說明頁的做法：用 Google 的 cros-flex-tools 套件裡的 package_flex_image 指令，把註冊權杖封進 ChromeOS Flex 映像檔。用這個映像檔安裝的機器，第一次開機就會自動註冊，不需要輸入帳密。

  • 需要：Chrome 管理員權限；Debian 或 Ubuntu 的 Linux 環境（可以用 Windows 的 WSL）；至少 35GB 空間；USB 做法要 8GB 以上隨身碟
  • 權杖格式：小寫 UUID，例如 12345678-90ab-cdef-1234-567890abcdef
  • 網路：官方提醒設定網路時「可能仍需與使用者互動」，例如現場選 Wi-Fi
  • 詳細指令照官方頁面做：Automatically enroll ChromeOS Flex devices。PXE 環境可參考官方 Mass deploy ChromeOS Flex（WDS）
重灌一定會清空資料
官方頁面沒有明講，但重新安裝作業系統會清空整顆硬碟。用過一段時間的機器，先請使用者把資料備份到雲端。

20出問題怎麼辦

看到的訊息或狀況可能原因怎麼處理
連線 C$：拒絕存取（Access is denied、錯誤 5）非網域電腦的遠端限制；或帳密錯誤；或帳號不是系統管理員在目標電腦執行第 12 章的 reg add；確認帳號在系統管理員群組；帳號格式可以試 電腦名稱\帳號
System error 67／找不到網路名稱電腦名稱打錯、不在同網段、電腦沒開機改用 IP；先 ping 看看通不通；確認同一個網路、沒有 AP 隔離
System error 53／找不到網路路徑；或逾時防火牆擋了檔案分享、網路設定檔是「公用」開「檔案及印表機共用」，網路改成「私人」
預檢：腳本沒產生結果S 模式不能執行 PowerShell；或防毒軟體擋了看第 7 章；暫時在防毒軟體加例外，或改用單台方法
precheck.ps1 出現一堆紅字語法錯誤、中文變亂碼檔案被另存成沒有 BOM 的編碼從工具資料夾重新複製一份，不要用記事本另存
預檢不合格：開機模式不是 UEFI／磁碟不是 GPT舊機用 Legacy 開機第 6 章；或直接排除這台
模擬測試出現 GetSupportedSize 相關錯誤defragsvc（磁碟重組服務）設成自動啟動agent.toml 取消註解 disable_defragsvc = true

22名詞解釋

ChromeOS Flex
Google 給一般 PC、Mac 用的免費 ChromeOS 版本，裝上後用起來跟 Chromebook 差不多
FRD（Flex Remote Deployment）
Google 官方的遠端轉換工具，在 Windows 上執行 agent.exe 就能把整台轉成 Flex
CEU（Chrome Education Upgrade）
讓 ChromeOS 裝置能註冊進學校 Google Admin Console、被集中管理的授權，一台一個，永久授權。企業版叫 Chrome Enterprise Upgrade
註冊權杖（enrollment token）
在 Admin Console 產生的一串碼，綁在組織單位上。FRD 拿它讓裝置自動註冊
授權池
組織買好、還沒指派給裝置的授權額度。買授權是先放進池子，裝置註冊那一刻才扣一個名額
未受管
沒有註冊進任何組織的 ChromeOS 裝置，等於個人用的機器
Intune
微軟的雲端裝置管理服務，要另外付費，可以把程式派送到 Windows 電腦
Entra ID
微軟的雲端帳號系統（舊名 Azure AD）。電腦「加入 Entra ID」代表用公司 Microsoft 帳號登入
PsExec
微軟 Sysinternals 的免費小工具，從一台電腦遠端在另一台電腦上執行程式，需要對方的系統管理員帳密
RMM
遠端監控管理平台，在每台電腦裝代理程式後，可以從雲端集中派送軟體與指令。Action1 是其中一種
UEFI／Legacy BIOS
電腦開機時先跑的韌體，UEFI 是新的、Legacy 是舊的。FRD 只支援 UEFI
GPT／MBR
磁碟分割表的格式，UEFI 配 GPT、Legacy 配 MBR
S 模式
Windows 的限制模式，只能裝 Microsoft Store 的 App，不能執行一般 exe
SMB／445 埠
Windows 的檔案分享機制與它用的網路埠。PsExec 靠它把檔案送過去，被防火牆擋住就連不上
.intunewin
Intune 專用的軟體封裝格式，要派送的檔案打包成這種格式才能上傳到 Intune 後台
PXE（網路開機）
電腦開機時不從硬碟、改從網路上的伺服器載入安裝程式，大型場域用來大量重灌
cros-flex-tools
Google 給 Linux 用的 Flex 工具套件，其中的 package_flex_image 可以把註冊權杖封進 Flex 映像檔
ONC
Google 定義的網路設定 JSON 格式，用來把 Wi-Fi 名稱密碼預先寫進 ChromeOS
dry_run（模擬測試）
FRD 只做檢查不動硬碟的模式，記錄會出現 InstallSkipped
Powerwash
ChromeOS 的恢復原廠設定，清掉本機所有資料與帳號
LocalAccountTokenFilterPolicy
Windows 的登錄設定，設成 1 才允許非內建 Administrator 的本機管理員帳號從遠端管理這台電腦
AP 隔離
Wi-Fi 基地台的設定，開了之後連同一個 Wi-Fi 的裝置彼此連不到，訪客網路常見
